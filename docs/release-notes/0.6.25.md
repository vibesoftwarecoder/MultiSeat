**This release fixes the USB forwarding panel refusing the person at the console.**

## What changes

- **The host's USB forwarding panel now opens for the console user** (#138). In 0.6.24 it answered `403 NotConsoleUser` to the person sitting at the host, and the dashboard showed "can only be seen and changed from the host's own desktop" even on the host's own desktop.
  - **Cause:** the access check refused every account MultiSeat has stored as a seat account. That list also holds ordinary Windows accounts that were only *linked* to MultiSeat, and the person at the console is often one of them.
  - **Now:** a seat account is one MultiSeat created, or one that hosts a live seat or has a saved seat preset. A linked account that does host a seat still counts as a seat account.
  - **Unchanged:** a seat user, another user, a service account, a dashboard reached over the network, and a seat user who moves their session to the console with `tscon` are all still refused.

## Who this affects

- **You, if you installed 0.6.24 and your own Windows account is linked to MultiSeat.** The USB card on the host was unusable for you. Nothing else in 0.6.24 was affected.
- Everyone else sees no change.

## How this was checked

- **Unit tests:** five new tests for which accounts count as seat accounts. The one that covers this bug fails with the 0.6.24 rule and passes now; the rule was removed on purpose to confirm it. The full suite finished with 1932 passed, 18 skipped and 0 failed.
- **The bug itself** was reproduced on the reference host with 0.6.24: a request from the console user's own session got `403 NotConsoleUser` on `127.0.0.1`, `[::1]` and `localhost`.

## Not verified

- **The USB panel in a real browser after this fix.** It has not yet been compared between a browser on the console and one inside a seat. That is the check that found this bug.
- **A seat user moving their session to the console** (`tscon`) is covered by a unit test of the rule, not measured on a live seat.

## Install

```powershell
.\scripts\install-service.ps1 -FromZip .\multiseat-windows-x64.zip
```

If an isolated Steam is running, the installer stops without changing anything; close Steam first, then run it again. Afterwards, confirm what landed:

```powershell
& 'C:\Program Files\MultiSeat\MultiSeat.Service.exe' --config
```

It should report `0.6.25`.
