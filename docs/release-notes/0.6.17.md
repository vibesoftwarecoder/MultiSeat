**This release lets you keep a specific physical controller confined to the console, so it never bleeds into a seat.**

## What was happening

Issue #92: `EnableHidHideCloaking` only ever isolated a seat's own virtual controller from other seats — it was deliberately built to never touch a real physical controller automatically, so a seat could never accidentally take someone's actual gamepad. That meant a physical controller plugged into the main PC had no way to be kept out of a seat, even though the exact same underlying mechanism (HidHide's per-session isolation) could do it.

## What changes

A new, opt-in `ExcludedPhysicalPadDevicePaths` setting lets you name a specific physical controller (found via `MultiSeat.Service.exe --hidhide`'s existing device listing) to confine to the console's own session. It reuses the exact same isolation mechanism seats already use, just pointed the other way, and self-heals on the existing health-check cadence — so it keeps working if the console session changes (a fast user switch, a logon/logoff) or if the controller wasn't plugged in yet when the service started. Empty by default, so nothing changes unless you configure it.

`--hidhide` now reports, for each configured path, whether it's present and whether both its device nodes are actually confined to the live console session.

## Who this affects

Anyone whose main PC has its own physical controller that shouldn't be usable from a seat.

## How this was checked

794 tests pass (16 new), 0 failures, mutation-checked — each new behavior reverted, confirmed its exact test fails, restored.

**What this doesn't confirm:** real confinement against an actual physical controller. This host has no gamepad attached to test against, so verification stopped at the code being correct and the diagnostic not crashing with the feature configured. This needs a real controller and a real host to confirm — which is exactly why this release exists, to get that real-world test.


## Known limitations

- **Seats capture the remote desktop surface, not a dedicated virtual display.** A Windows constraint, not a regression.
- **The seat refresh rate is one value for the whole host**, not one per seat.
- **The keyboard/mouse isolation setting is still a known no-op** — see #92's thread for the current understanding.
