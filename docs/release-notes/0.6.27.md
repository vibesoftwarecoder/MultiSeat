**This release stops MultiSeat from redirecting printers, serial ports and drives into seat sessions. It may fix the Print Spooler load some users see with several seats, but that is not confirmed.**

## What changes

- **Seats no longer get the host's printers, serial ports or drives** (#145, refs #136). The `Default.rdp` file MultiSeat writes for each seat did not turn these off, and Windows redirects printers by default. So each seat could get a copy of the console user's printers and create its own print queues on the host's one Print Spooler. The file now sets `redirectprinters:i:0`, `redirectcomports:i:0` and an empty `drivestoredirect`. The clipboard is unchanged.

## Who this affects

- **Everyone.** The change applies to every seat. Most people will see no difference.
- **Anyone who prints, or uses a serial port or a redirected drive, from inside a seat.** Those no longer appear in the seat. If you do this, please tell us in an issue.
- **Anyone who saw CPU load grow with each seat, with the Print Spooler and Windows Defender busy** (#136). This may help. We have not reproduced that problem, so please report either way.

The setting is read when a seat connects. A seat that is already running should keep its current printers until it is provisioned again.

## How this was checked

- **Unit tests:** One test checks that all three keys are written for both audio modes, with and without a screen size. Another checks that the clipboard is left alone. With the fix removed, the four redirect cases fail.
- **CI:** The build, test, dashboard audit and script lint all passed on the change.

## Not verified

- **Not tried on a seat.** Nobody has checked on a live seat that the printers disappear, or that the Print Spooler load drops.
- **That printer redirection causes #136.** It is a hypothesis that fits the report. If it is wrong, this change does nothing for that issue.
- **Whether anyone relies on printers, ports or drives inside a seat.** We assumed seats do not need them, and we have not checked.

## Install

```powershell
.\scripts\install-service.ps1 -FromZip .\multiseat-windows-x64.zip
```

If an isolated Steam is running, the installer stops without changing anything; close Steam first, then run it again. Afterwards, confirm what landed:

```powershell
& 'C:\Program Files\MultiSeat\MultiSeat.Service.exe' --config
```

It should report `0.6.27`.
