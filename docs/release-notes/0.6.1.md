**A packaging fix. If you installed 0.6.0 from the zip, nothing about the running service changed —
this only fixes how the release installs.**

## What was wrong with 0.6.0

The 0.6.0 notes told you to run `.\scripts\install-service.ps1`, but the asset contained only the
binary. There was no `scripts` folder inside it. So the instructions worked only if you had already
cloned the repository — 0.6.0 removed the .NET SDK and Node requirement, but not the clone, which
is not what its notes claimed.

## Install

Download `multiseat-windows-x64.zip`, extract it anywhere, and run both scripts from inside the
extracted folder:

```powershell
.\prerequisites\install-prerequisites.ps1     # drivers - needed either way
.\scripts\install-service.ps1 -FromZip .
```

**No clone required.** The asset now carries the installer scripts and the prerequisite installer
alongside the binary, and it is still self-contained — no .NET SDK, no .NET runtime, no Node.

`-FromZip` accepts either the extracted folder, as above, or the `.zip` file itself if you would
rather not extract it first.

That completeness costs 0.66 MB: the download went from 53.10 MB to 53.76 MB.

## Two things the installer is careful about

**It does not put the installer inside your install directory.** `scripts`, `prerequisites` and
`README.md` ship in the asset but are deliberately left out of `C:\Program Files\MultiSeat`. A
stale copy of an installer sitting in the install directory is exactly the sort of thing that gets
run by mistake later.

**It will not delete the folder you extracted.** When `-FromZip` is given a directory, that
directory is yours — the installer reads it in place and cleans up only staging directories it
created itself. An earlier version of this change would have deleted it, along with the installer
being run from it.

As in 0.6.0, the payload is verified before your existing install is touched, and a zip that is not
self-contained is refused rather than half-installed.

## Still true from 0.6.0

- The version comes from one file. A `v*` tag that disagrees with `version.txt` fails the release
  rather than shipping a binary that claims a version no release has.
- `& 'C:\Program Files\MultiSeat\MultiSeat.Service.exe' --config` reports the deployed version,
  commit and resolved settings. Worth running before reporting a bug.
- Keyboard/mouse isolation (`EnableKeyboardMouseIsolation`) is off by default and remains a no-op.

## Known limitations

- The `-FromZip` install path is verified by CI and tested against good and deliberately broken
  assets, but has still not been run on a fresh host. If you hit something, please open an issue
  with the output of `--config`.
