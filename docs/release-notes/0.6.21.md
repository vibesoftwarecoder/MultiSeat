**This release adds experimental, opt-in Steam isolation, so each seat can run its own Steam beside the console's Steam. It is off by default. If you do not turn it on, nothing about how your seats behave changes.**

## What was happening

Steam allows one running client per machine. A second `steam.exe` finds the first through shared state: a named IPC channel, the `SteamPID` value in the machine-wide `HKLM\SOFTWARE\WOW6432Node\Valve\Steam` key, and the `TempAppCmdLine` hand-off. Every seat shares that state with the console. So a Steam started in a seat could hand its launch to the console's Steam, or end it, instead of starting a client of its own.

## New: Steam isolation (experimental, off by default)

MultiSeat can now start Steam through its own native launcher inside the seat's existing Windows user and session. The launcher hooks `steam.exe` so that its IPC name, browser cache folders and the registry values above are specific to that seat's session and user. Nothing is installed into Steam, and no system DLL is replaced.

**To turn it on**, add this to `appsettings.local.json` and restart the MultiSeat service:

```json
{
  "MultiSeat": {
    "SteamIsolationEnabled": true
  }
}
```

The default is `false`. The full guide is `docs/steam-isolation.md`. The design notes and measurements for the shortcut shim are in `docs/design/steam-shim.md`.

What it covers once it is on:

- **Launches that MultiSeat starts.** An app launch from the dashboard or API, and `MultiSeat:LaunchOnConnect`, goes through the launcher when the program is an absolute path to `steam.exe`. Other programs are unchanged. A relative Steam path is refused.
- **The Steam tile in Moonlight.** When MultiSeat copies Apollo's app list into a seat, Steam entries (a `steam.exe` command, or a `steam://` link such as the stock "Steam Big Picture" entry) are rewritten to start through the launcher.
- **Shortcuts, links and autostart.** A new helper, `MultiSeat.SteamShim.exe`, takes the place of `steam.exe` in the Steam shortcuts, the `steam://` handler, the Run entry and the taskbar and Startup shortcuts. If the account already has an isolated Steam, the shim hands the command to it. Otherwise it starts one and holds a lock until that Steam has registered, so a second click cannot start a second client. Seat accounts are set up when they are provisioned. The console user is included by default (`SteamShimIncludeConsole`), because a plain Steam on the console and an isolated Steam in a seat cannot both stay up. Set `SteamShimEnabled` to `false` to turn the shim off.
- **Every shim edit can be undone.** Each original is recorded in `steam-shim-backup.json` before anything is changed. `MultiSeat.Service.exe --steam-shim-undo` restores them and needs no running service. The uninstall script runs it first. Turning isolation or the shim off also undoes the edits at the next service start.
- **Restarts and child processes.** Steam restarts itself and starts helper processes. The hook is placed where every Windows process-creation call ends, so a restart through `CreateProcessAsUser`, or through an unquoted path with spaces, is still isolated. The hook writes a line to `launcher.log` in the seat user's profile for each restart it isolates or refuses.
- **A second Steam in the same account.** `SteamPID` is moved to the user's own `HKCU\Software\Valve\Steam`, and a `--forward` mode hands a second command to the running Steam. Before this, a second launch started a full client and replaced the first one's login.
- **It fails closed.** If the launcher, a hook or the Steam an entry would run is missing, that Steam entry is left out of the seat's app list and the service logs an error that names it and gives the reason. Steam is not started without the hook.
- **Plain Steam is reported.** The service logs one warning per process for a `steam.exe` that has no hook, so a launcher that bypasses the shim shows up.
- **Game launches.** A hook bug that refused some game launches with error 87 is fixed. It read leftover text after the environment block as part of the block.

New settings, all under `MultiSeat`: `SteamIsolationEnabled` (default `false`), `SteamIsolationLauncherPath`, `SteamIsolationReadyTimeoutSeconds` (default 180, limited to 10 seconds through 15 minutes), `SteamShimEnabled` (default `true`, and it acts only while isolation is on) and `SteamShimIncludeConsole` (default `true`).

Two things to know before you turn it on:

- Close Steam in the target seat first. A Steam started by hand from Explorer, or by another program that bypasses the shim, is not isolated.
- A game started from Explorer does not inherit the isolated Steam's environment. Start games from that Steam's library.

## Release zip and installer

- **The release zip now carries the native helpers** in `SteamIsolation\`: `MultiSeat.SteamLauncher.exe`, `MultiSeat.SteamLauncher32.exe`, `MultiSeat.SteamHook.dll`, `MultiSeat.SteamHook32.dll` and `MultiSeat.SteamShim.exe`. The release workflow builds them on `windows-2022`, runs the native checks, and refuses to publish an asset that lacks any of the five.
- **An upgrade keeps them.** The installer replaces the whole install folder. A payload that ships `SteamIsolation\` replaces the old copy. A payload that does not (an older release, or a source install without the switch) leaves the existing folder as it was. A payload that carries only some of the files is refused before anything is touched.
- **Source installs:** `.\scripts\install-service.ps1 -BuildSteamIsolation` builds the helpers fresh on that run. It needs the Visual Studio 2022 C++ tools and CMake. If the build fails, the install fails. Without the switch, nothing changes.
- With the feature off, the helpers sit unused in the install folder.

## Other changes

- A launch inside a seat that times out waiting for the Steam helper now returns **504 Gateway Timeout**. One where the helper exits early now returns **500**. They used to come back as an unexplained 500 and as a 400 that blamed the request.
- A launch that is refused before anything starts (a bad Steam path, a missing helper) still returns **400**, with the reason.

## How this was checked

The Steam isolation code has unit tests in the MultiSeat suite and native policy checks for both x64 and x86. Launcher and game-launch smoke scripts run against safe test programs, not the real Steam. They cover launch, restart through several creation calls, readiness, hand-off to a running Steam, and cleanup. The same scripts run in CI on every push to the native folder, and again in the release workflow before the zip is built. The shim and installer behaviour is covered by tests of the shortcut edits, the backup and undo, and the payload checks.

**Not verified:** this release has **not been runtime-tested on a live seat** by the maintainers. The tests above do not cover a real Steam login, Steam updates, real games, anti-cheat, or several real seat sessions running at once. `docs/steam-isolation.md` also notes limited manual reports from outside testing. Treat the feature as experimental, and expect rough edges.

## Known limitations

- Steam isolation is experimental and off by default.
- Steam started outside MultiSeat's launcher and shim is not isolated.
- A game started from Explorer is not isolated.
- Seats capture the remote desktop surface, not a dedicated virtual display. A Windows constraint, not a regression.
- On at least one host the scale override is still ignored (issue #93). This release does not change that.

```powershell
.\prerequisites\install-prerequisites.ps1     # drivers - needed either way
.\scripts\install-service.ps1 -FromZip .
```

Afterwards, confirm what landed:

```powershell
& 'C:\Program Files\MultiSeat\MultiSeat.Service.exe' --config
```

It should report `0.6.21`.
